## 1. 概述

OTA 包统一用 `build/make_ota.sh` 制作，不再手工准备 `target_package` 或手工改 XML。

| 模式 | 命令参数 | 升级分区 | 用途 |
|------|----------|----------|------|
| 全量包 | `full`（默认，可省略） | 全部 11 个分区 | 首次升级、跨大版本 |
| 最小包 | `minimal` | `system` / `vendor` / `updater` | 日常开发验证，不涉及内核与 bootloader |
| 差分包 | `diff` | 按分区做 bsdiff | 小版本增量 |
| SD/USB 包 | 后面追加 `sdcard` | 同 full / minimal | 无 hdc 环境时升级 |

## 2. 需要用户编辑的文件

每个产品一套，位于 `device/board/spacemit/<product>/updater/updater_config/`。**发布新版本时，通常只需要改下面第 1、2 项**，其余保持不动。

### 2.1 目标版本号（必改）

文件：`vendor/spacemit/<product>/etc/param/product_<product>.para`

```text
const.product.incremental.version="V0.1"
```

打包时 `build/make_ota.sh` 用 `sed` 把这里读到的值写进 **`out/<product>/packages/phone/images/updater_config/updater_specified_config.xml`** 的 `softVersion` 字段。

也就是说：

- 源码模板 `device/board/spacemit/<product>/updater/updater_config/*.xml` 里的 `softVersion` **不会被修改**，写什么都不影响打包结果
- 想改目标版本，只改 `product_<product>.para` 这一处即可，三份 XML 模板不用同步

### 2.2 允许升级的源版本（必改）

文件：`device/board/spacemit/<product>/updater/updater_config/VERSION.mbn`

```text
V0.1
V0.2
```

每行一个版本。设备当前版本必须命中其中一行，否则升级直接被拒绝。发布 V0.3 后，如果还要让 V0.1 的设备能一次性升上来，就把 `V0.1` 保留在列表里。

### 2.3 允许升级的板名（一般不改）

文件：`.../updater_config/BOARD.list`

```text
musepaper2
default
```

设备实际板名必须与其中某一行完全一致（区分大小写）。新增硬件形态时才需要改。

### 2.4 分区清单（一般不改）

- `updater_specified_config_full.xml`：全量包的分区清单
- `updater_specified_config_minimal.xml`：最小包，只含 `system` / `vendor` / `updater`
- `updater_specified_config_diff.xml`：差分包。`compType="1"` 做差分，`compType="0"` 全量写入

只有在增删分区时才改。`softVersion` 字段会被脚本自动覆盖，手工改没有意义。

## 3. 打包

### 3.1 前置条件

```bash
./build.sh --product-name musepaper2 --ccache --prebuilt-sdk
```

打包还依赖 `xmltodict`、`asn1crypto`、`cryptography` 三个 Python 库，缺失时脚本会自动安装。

### 3.2 常用命令

```bash
# 全量包（默认）
bash build/make_ota.sh musepaper2

# 最小包
bash build/make_ota.sh musepaper2 minimal

# SD 卡 / USB 升级包
bash build/make_ota.sh musepaper2 full sdcard
bash build/make_ota.sh musepaper2 minimal sdcard

# 差分包
bash build/make_ota.sh musepaper2 diff /some/path/images_old
bash build/make_ota.sh musepaper2 diff /some/path/images_old V0.1   # 旧版本号识别不出来时手动指定
```

### 3.3 差分包需要先保存旧版本镜像

```bash
# 旧版本编译完成后，把整个 images 目录复制留档
cp -r out/musepaper2/packages/phone/images /some/path/images_old
```

旧版本**不需要**打过 OTA 包。脚本会自动从旧 `vendor.img` 里读出版本号；读不到时用上面命令的最后一个参数手动指定。

### 3.4 打包产物

输出到 `out/musepaper2/ota/<版本>_<模式>_<时间戳>/`：

```text
musepaper2_V0.1_ota_full_202610211430.zip   # 升级包
config.json                                  # 在线升级服务器配置模板
config.json.README.txt                       # 字段说明
```

脚本会同时打印升级包的**大小和 SHA256**，后面做在线升级时要用。

### 3.5 编译 A/B 槽镜像

**改一个地方：**

`vendor/spacemit/musepaper2/config.json:152`，`startup` → `init` 组件：

```json
{
  "subsystem": "startup",
  "components": [
    { "component": "init", "features": [ "init_feature_ab_partition = true" ] }
  ]
}
```

把它从 `false` 改成 `true`，然后重新编译：

```bash
./build.sh --product-name musepaper2 --ccache
```

**不需要改 `device.gni`。** [device.gni:44](src/device/board/spacemit/musepaper2/device.gni#L44) 已经把 `enable_ab_update` 绑定到它，并有 `assert` 保证两者一致：

```gn
enable_ab_update = init_feature_ab_partition
```

**改完之后这三处会自动换成 A/B 版本：**

| 位置 | 非 A/B | A/B |
|---|---|---|
| 分区表 | `partition_universal.json` | `partition_universal_ab.json` |
| 启动参数 | `env_k1-x_noab.txt` | `env_k1-x.txt`（含 `bootslots=2`） |
| 编译期 | — | `init` 带 `partitionslot.cpp`，`libslotinfo` 定义 `UPDATER_AB_SUPPORT` |

分区表多了成对分区和一个 `bootctrl`：

```text
sys_prod_a / sys_prod_b
chip_prod_a / chip_prod_b
system_a / system_b
vendor_a / vendor_b
bootctrl
```

## 4. 升级操作

### 4.1 本地升级（hdc 推包）

用普通 `full` / `minimal` 包：

```bash
hdc file send musepaper2_V0.1_ota_full_202610211430.zip /data/updater.zip
hdc shell write_updater updater /data/updater.zip
hdc shell reboot updater
```

升级完成后设备自动重启。验证版本：

```bash
hdc shell param get const.product.incremental.version
```

### 4.2 SD 卡 / USB 升级

把 `sdcard` 模式打出的包重命名为 `updater.zip`，放到 SD 卡：

```text
/sdcard/updater/updater.zip
```

然后让设备进入 updater 模式（`write_updater` + `reboot updater`，或刷机时进入），在界面上选 SD 卡升级。

### 4.3 在线升级

**第一步**，在设备上配置服务器地址：

```text
# vendor/spacemit/<product>/etc/param/product_<product>.para
update.server.url=https://ota.example.com/config.json
update.server.verify_cert=1
```

`update.server.url` 需填**完整的 config.json 地址**，支持域名、自定义端口和自定义路径；走 HTTPS 还是 HTTP 由 URL 的协议头决定。

**第二步**，把 zip 和打包生成的 `config.json` 放到服务器，只把 `url` 改成实际下载地址即可。

> `size` 和 `verifyInfo` 已由打包脚本按实际 zip 自动计算填好，**不需要手工改**。下面 JSON 中的这两个值仅作示意。

```json
{
  "searchStatus": 0,
  "checkResults": [{
    "descriptPackageId": "musepaper2-ota-full",
    "url": "https://YOUR_SERVER/updates/musepaper2_V0.1_ota_full_202610211430.zip",
    "size": 123456789,
    "verifyInfo": "<zip 的 SHA256>",
    "versionCode": "V0.1",
    "versionName": "V0.1",
    "packageType": 1,
    "otaType": 0
  }],
  "descriptInfo": [{ "descriptionType": 0, "content": "System update to V0.1" }]
}
```

**第三步**，设备上进入 设置 → 系统 → 软件更新 → 检查更新。

## 5. 重点关注

### 5.1 三个必须对上的值

升级失败绝大多数是这三个值对不上：

| 项目 | 设备侧来源 | 包侧配置 |
|------|-----------|----------|
| 目标版本 | 设备侧 `const.product.incremental.version` | 打包时从 `product_<product>.para` 读取，自动写入 XML 的 `softVersion` |
| 源版本 | 设备当前 `const.product.incremental.version` | `VERSION.mbn` |
| 板名 | `const.build.product`（读不到时用 `ohos.boot.hardware`） | `BOARD.list` |

排查命令：

```bash
hdc shell param get const.product.incremental.version
hdc shell param get const.build.product
hdc shell param get ohos.boot.hardware
```

### 5.2 sdcard 包不能当普通包用

`sdcard` 包内多了 hash 校验字段（TLV 0x06/0x07），**只有 SD 卡 / USB 方式升级才会解析**。用 hdc 推包或在线升级推 sdcard 包，设备端会报错中断。反过来，普通包也不能放进 `/sdcard/updater/` 做 SD 卡升级。

### 5.3 在线升级的 `size` 和 `verifyInfo` 必须和实际 zip 一致

这两个值脚本已按当次打出的 zip 自动填好，和 zip 是配套的，正常流程下不需要动。

需要留意的是：**一旦换成另一个 zip**（重新打包了一次），就要连 `config.json` 一起换成同一个输出目录里的那份，不能只换 zip、留着旧的 `config.json`，否则设备下载后校验失败。只改文件名不影响这两个值。

另外，`config.json` 必须是纯 JSON，不能带 `//` 或 `/* */` 注释。

### 5.4 版本号要写带引号

`product_<product>.para` 中必须是这一整行：

```text
const.product.incremental.version="V0.1"
```

引号不能省，否则脚本读不到版本，会直接报错退出。

### 5.5 差分包的旧镜像要整目录留档

`diff` 模式需要完整的旧版本 `images` 目录，不能只留 `system.img` / `vendor.img`。建议每个发布版本都留一份，命名带版本号。

### 5.6 系统分区要求

设备需要 `updater` 和 `misc` 两个分区，其中 `misc` 是没有文件系统的裸分区，用来存升级命令。缺少或读不到 `misc` 时，`reboot updater` 会直接重启而不进入升级模式。
