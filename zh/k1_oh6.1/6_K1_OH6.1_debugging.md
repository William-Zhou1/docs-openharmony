## 1. 调试工具和方法

### 1.1 串口调试

系统默认支持串口调试，波特率为 **115200**。
通过串口可查看 **U-Boot**、**Kernel** 以及 **OpenHarmony init** 进程的相关日志输出。

#### 1.1.1 调整串口打印等级

##### 1.1.1.1 仅本次启动有效

串口中执行如下命令即可：

```bash
echo 8 > /proc/sys/kernel/printk
```

##### 1.1.1.2 持续生效

主要通过修改 `env_k1-x.txt` 文件中的 `loglevel` 值来实现，有 2 种方式：

1. 修改代码并编译固件

   - 修改 `device/board/spacemit/xxx/kernel/boot/bootfs/env_k1-x.txt` 中 `loglevel` 的值
   - 重新编译固件并烧录即可
2. 系统中直接修改，按照如下步骤进行：

   - 挂载内核

   K1 平台使用 eMMC 存储，分区设备为 `/dev/block/mmcblk2pX`，bootfs 分区为 `/dev/block/mmcblk2p5`，也可以直接用符号链接 `/dev/block/by-name/boot`：

   ```bash
   # cd dev/block/
   # ls
   by-name  loop5         mmcblk2p1   mmcblk2p3  mmcblk2p9  ram12  ram4
   loop0    loop6         mmcblk2p10  mmcblk2p4  platform   ram13  ram5
   loop1    loop7         mmcblk2p11  mmcblk2p5  ram0       ram14  ram6
   loop2    mmcblk2       mmcblk2p12  mmcblk2p6  ram1       ram15  ram7
   loop3    mmcblk2boot0  mmcblk2p13  mmcblk2p7  ram10      ram2   ram8
   loop4    mmcblk2boot1  mmcblk2p2   mmcblk2p8  ram11      ram3   ram9
   #
   # mount /dev/block/mmcblk2p5 /tmp
   # cd /tmp
   # ls
   Image.itb  bianbu.bmp  env_k1-x.txt  k1-x_MUSE-Paper2.dtb  lost+found
   ```

   > 说明：bootfs 里的 dtb 文件名随方案不同，例如 MUSE Paper2 是 `k1-x_MUSE-Paper2.dtb`、deb1 是 `k1-x_deb1.dtb`，与本方案 `build_kernel.sh` 中 `KERNEL_DTB` 对应。挂载后 `/tmp` 的原有内容会被 bootfs 覆盖，调试时不要往 `/tmp` 里放其他东西。

   - 使用 `hdc` 工具拉取 `env_k1-x.txt`，修改后，再推入 `/tmp` 文件夹

   ```bash
   D:\>hdc file recv /tmp/env_k1-x.txt
   FileTransfer finish, Size:134 time:23ms rate:5.83kB/s

   D:\>hdc file send env_k1-x.txt /tmp/
   FileTransfer finish, Size:134, File count = 1, time:8ms rate:16.75kB/s
   ```

   - 取消挂载内核，重启即可生效

   > 注意：命令是 `umount`，设备上没有 `unmount` 这个命令。

   ```
   # umount /tmp
   # reboot
   ```

### 1.2 HDC

HDC（Harmony Device Connector）功能类似于 Android 的 ADB，支持 **USB** 和 **TCP** 两种连接模式。
在使用 TCP 模式时，默认端口为 **55555**。
配置文件路径：`device/board/spacemit/xxx/cfg/default.para`
示例如下：

```bash
persist.hdc.mode=usb,tcp
persist.hdc.port=55555
```

### 1.2.1 主机支持 HDC

#### 1.2.1.1 Windows 系统

Windows 系统将 `hdc.exe`（[点我下载](https://archive.spacemit.com/tools/openharmony/hdc.zip)）放在特定目录，并设置环境变量路径。

#### 1.2.1.2 Ubuntu 系统

- 安装依赖项‌：打开终端，输入以下命令来更新软件包列表并安装必要的开发工具和库

  ```bash
  sudo apt-get update
  sudo apt-get install build-essential libstdc++6 libc++1·
  ```
- 下载 HDC 工具包‌：前往 OpenHarmony 官网下载适用于 Linux 平台的最新版 HDC 工具压缩包。将其放置于合适位置后进行解压操作，请根据实际情况调整解压路径

  ```bash
  tar -zxvf hdc_std_<version>_linux.tar.gz -C /opt/hdc/
  ```
- 设置环境变量‌：编辑用户的 shell 初始化脚本（如 `.bashrc`），添加以下行至文件末尾：

  ```bash
  export PATH=$PATH:/opt/hdc/bin
  source ~/.bashrc
  ```
- 验证安装成功与否‌：在新的终端窗口里尝试运行简单的帮助指令以确认一切就绪，如果能够看到详细的帮助文档，则表明整个过程顺利完成

  ```bash
  hdc help
  ```

```bash
#
```

### 1.7 服务管理

`service_control` 用于启停由 init 托管的 native 服务，服务名即 `/system/etc/init/` 下对应 cfg 文件里定义的 `name`。K1（OH6.1）的音频服务为 `audio_server`（对应 `audio_server.cfg`）。

<table>
<tbody>
<tr>
<td>命令</td>
<td>用途</td>
</tr>
<tr>
<td>service_control start audio_server</td>
<td>启动音频服务</td>
</tr>
<tr>
<td>service_control stop audio_server</td>
<td>停止音频服务</td>
</tr>
<tr>
<td>service_control</td>
<td>不带参数执行，打印命令用法</td>
</tr>
</tbody>
</table>

查看设备上实际存在哪些服务：

```bash
# 列出所有由 init 托管的服务名
ls /system/etc/init/*.cfg /vendor/etc/init/*.cfg 2>/dev/null

# 查看某个服务当前是否在运行
ps -A -o PID,USER,CMD | grep audio_server
```

> 注意：`service_control` 对**不存在的服务名同样返回 0**，不会报错。因此不能用返回值判断服务是否真的启动成功，必须配合 `ps` 或 `hilog` 确认。
>
> 另外：镜像里保留了 `third_party/pulseaudio` 的编译产物，但 OH6.1 的音视频框架已改为 `audio_server`，`pulseaudio` 并没有作为 init 服务启动，不要再按旧文档执行 `service_control stop pulseaudio`。

### 1.13 wukong

wukong 是 OpenHarmony 自带的稳定性测试工具（`/system/bin/wukong`），通过随机或指定的触摸、滑动、按键、应用切换等事件对系统和应用做压力测试。

| 命令 | 说明 |
|------|------|
| `wukong exec` | 随机测试 |
| `wukong special` | 专项测试（指定坐标点击、滑动、录制回放等） |
| `wukong focus` | 聚焦测试（对指定控件类型集中注入事件） |
| `wukong appinfo` | 列出所有可测试应用的 BundleName 和 AbilityName |

每个子命令都可以用 `-h` 查看完整参数，例如 `wukong exec -h`。

#### 1.13.1 随机测试

```bash
# 全局随机测试：随机种子 10，间隔 500ms，应用切换占 20%、触摸占 60%，共执行 20 次
wukong exec -s 10 -i 500 -a 0.2 -t 0.6 -c 20

# 只测试指定应用（先用 wukong appinfo 查包名），持续 10 分钟
wukong exec -b com.ohos.settings -T 10 -i 500
```

常用参数：

| 参数 | 说明 |
|------|------|
| `-c, --count` | 执行次数，与 `-T` 二选一 |
| `-T, --time` | 测试时长（单位：分钟） |
| `-i, --interval` | 事件间隔（单位：ms） |
| `-s, --seed` | 随机种子，相同种子可复现同样的事件序列 |
| `-b, --bundle` | 白名单，只测试指定应用，多个用逗号分隔 |
| `-p, --prohibit` | 黑名单，不测试指定应用 |
| `-a, --appswitch` | 应用切换事件比例（0~1） |
| `-t, --touch` | 触摸事件比例 |
| `-S, --swap` | 滑动事件比例 |
| `-k, --keyboard` | 键盘事件比例 |
| `-H, --hardkey` | 物理按键事件比例 |
| `-C, --component` | 控件事件比例 |
| `-I, --screenshot` | 每次事件后截图 |

#### 1.13.2 测试结果

每次测试在 `/data/local/tmp/wukong/report/<日期_时间>/` 下生成一个目录：

| 文件 | 说明 |
|------|------|
| `wukong.log` | 测试过程中注入的每个事件 |
| `wukong_report.csv` | 事件统计报告 |
| `exception/` | 测试过程中出现的 crash 等异常 |

导出到 PC：

```bash
hdc file recv /data/local/tmp/wukong/report D:/
```

测试过程中出现的 cppcrash / jscrash 也会记录在 `/data/log/faultlog/faultlogger/` 下，分析方法见 3.2.3 节。

## 3. 常见问题调试手段

### 3.1 外设

#### 3.1.1 屏幕背光无法调节

K1 平台的背光节点在 `/sys/class/backlight/soc:lcd_backlight/`（不是 `/sys/class/backlight/backlight/`），可以先确认当前节点名：

```bash
# ls /sys/class/backlight/
soc:lcd_backlight

# cat /sys/class/backlight/soc:lcd_backlight/max_brightness
255
```

- 通过查看和设置节点 `/sys/class/backlight/soc:lcd_backlight/brightness` 来确认驱动是否正常
- 如果设置上述节点亮度无变化，说明驱动存在问题，需要查驱动，重点查看背光对应的 PWM 是否正常工作
- 如果设置上述节点亮度有变化，说明是 OH 上层的问题，可以通过命令 `power-shell display -s xxx(100>xxx>0)` 来查看亮度是否有变化

### 3.2 系统

#### 3.2.1 替换内核

- 挂载 bootfs 分区，可替换 `Image.itb` 和 `.dtb` 文件

K1 平台各方案对应的 dtb 如下（`dtb` 文件名不同方案不一样）：

| 方案 | dtb 文件 | 内核源码 dts |
|------|----------|--------------|
| musepaper2 | `k1-x_MUSE-Paper2.dtb` | `k1-x_MUSE-Paper2.dts` |
| musepaper | `k1-x_MUSE-Paper.dtb` | `k1-x_MUSE-Paper.dts` |
| musepipro | `k1-x_MUSE-Pi-Pro.dtb` | `k1-x_MUSE-Pi-Pro.dts` |
| deb1 | `k1-x_deb1.dtb` | `k1-x_deb1.dts` |

以 musepaper2 为例：


- 通过 `hdc` 将更新的内核或者 `dtb` 文件推入 `/tmp` 文件夹

#### 3.2.2 进入 U-Boot

有 2 种方法：

- 开机后，hdc 连接后或者串口连接后，执行 `reboot uboot`，重启后会进入 U-Boot
- 连接串口，关机后，串口输入按住 s 键，上电开机，进入 U-Boot

#### 3.2.3 cppcrash

##### 3.2.3.1 常规 cppcrash 处理方法

   ```bash
   index 17dbd73..f7164bf 100755
   --- a/k1/tools/ddr_bw/BUILD.gn
   +++ b/k1/tools/ddr_bw/BUILD.gn
   @@ -6,6 +6,7 @@ cflags_c_common = [
      "-Wno-unused-function",
      "-Wno-pointer-to-int-cast",
      "-Wno-deprecated-non-prototype",
   +  "-O0",
    ]

    cflags_cc_common = [
   ```

#### 3.2.4 打印堆栈

在调试或者跟踪代码的时候，经常需要打印函数调用栈，可以通过调用 `printCallers` 接口来实现，具体的接口如下：

```cpp
#include <execinfo.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#define MAX_FRAMES 20
void printCallers()
{
    int layers = 0, i = 0;
    char ** symbols = NULL;
    
    void * frames[MAX_FRAMES];
    memset(frames, 0, sizeof(frames));
    layers = backtrace(frames, MAX_FRAMES);
    for (i=0; i<layers; i++) {
        printf("Layer %d: %p\n", i, frames[i]);
    }
    printf("------------------\n");
    
    symbols = backtrace_symbols(frames, layers);
    if (symbols) {
        for (i=0; i<layers; i++) {
            printf("SYMBOL layer %d: %s\n", i, symbols[i]);
        }
         free(symbols);
    }
    else {
        printf("Failed to parse function names\n");
    }
}
```

将上面的接口放入要打印堆栈的文件中，调用 `printCallers` 进行打印即可。
